# Eunomia Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Eunomia, the FMUP · IA activity design assistant: a static front end next to Themis, a small Node server that runs the interview, calls IAedu, validates every section, and publishes approved fichas to `biblioteca/`.

**Architecture:** The code leads and the model writes. The server holds the interview state machine, the validators and the review workflow. It calls IAedu only for bounded writing tasks. The front end is vanilla JS with no build step, like Themis. The library is `.qmd` files committed to this repo by the server through the GitHub contents API.

**Tech Stack:** Node 22 (`node:http`, `node:test`, `node:crypto`, global `fetch`/`FormData`), `ajv` (JSON Schema), `mammoth` (.docx to text), vanilla HTML/CSS/JS, `jsdom` for front-end tests, Quarto 1.9, Docker, GitHub Actions, Caddy.

**Spec:** `docs/superpowers/specs/2026-11-14-eunomia-design.md` (approved 2026-11-14). Read it before any task. Section numbers below (for example "spec 6.8") point to it.

## Global Constraints

- Node 22. Server runtime dependencies: `ajv`, `mammoth` only. Front end: no dependencies, no build step, no CDN.
- All user-facing text in European Portuguese, pre-1990 spelling as in the Quadro ("actividade", "objectivo", "correcção", "directamente"), "estudantes" not "alunos", "doentes" not "pacientes". No emojis in any file or output.
- API base path: `/fmup-ia/eunomia/api` (the app receives the full path; Caddy uses `handle`, not `handle_path`). Container port 3000. Health route `GET /fmup-ia/eunomia/api/saude`.
- IAedu endpoint: `POST {IAEDU_BASE_URL}/agent/{agentId}/stream`, default base `https://api.iaedu.pt/agent-chat/api/v1`. Header `x-api-key`. Multipart fields `channel_id`, `thread_id`, `user_info` (`"{}"`), `message`; optional `user_context` (JSON-encoded object only). Never set Content-Type by hand.
- Environment variable names (values never in git): `EUNOMIA_SECRET` (32+ chars), `EUNOMIA_DATA` (default `./data`), `EUNOMIA_DAILY_LIMIT` (default 200), `EUNOMIA_DRAFT_RETENTION_DAYS` (default 365), `IAEDU_BASE_URL`, `IAEDU_API_KEY`, `IAEDU_AGENT_ID`, `IAEDU_CHANNEL_ID`, `IAEDU_ALT_API_KEY`, `IAEDU_ALT_AGENT_ID`, `IAEDU_ALT_CHANNEL_ID`, `GITHUB_TOKEN`, `GITHUB_REPO` (default `tiagojct/fmup-ia`), `GITHUB_BRANCH` (default `main`), `COMMIT_NAME`, `COMMIT_EMAIL`.
- Own-key request headers: `X-Iaedu-Key`, `X-Iaedu-Agent`, `X-Iaedu-Channel`. Never stored, never logged.
- The model never writes `regime_ia`, `referencias` or `declaracao`. These come from code.
- Draft states (spec 6.9): `rascunho`, `submetida`, `devolvida`, `aprovada`, `rejeitada`, `substituida`.
- Commit messages: imperative, no AI co-author or session lines. The library commit message is `biblioteca: add <slug> (<author>)`.
- Do not edit `training/fichas/*.qmd`. Do not copy Themis rule or clause code: load it.
- Generated `.qmd` must pass `scripts/check-content.py`: no bare `@` outside code (escape as `\@`).

## Review Focus

- The IAedu stream ends with an `error` line or with no `message` line after tokens. Expected: an `IaeduError` with a Portuguese message; nothing is stored as a generated section. Test in Task 4.
- Two browser tabs save the same draft. Expected: the second save with an old `rev` gets 409 and a message to reload, not a silent overwrite. Test in Task 7.
- A teacher pastes materials that look like patient data (a 9-digit number labelled SNS or utente, a NIF, a date of birth next to a name). Expected: a warning, and nothing goes to IAedu until the teacher confirms. Test in Task 10.
- An own key is wrong (IAedu 401). Expected: "A chave IAedu indicada não é válida." and no silent fallback to the shared key. Test in Task 9.
- The GitHub commit fails on approval (network error, 409 sha conflict). Expected: the submission stays `submetida`, the reviewer sees the error and can retry. Two fichas with the same title get different slugs. Tests in Task 11.
